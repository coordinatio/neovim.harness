# Agents

Neovim Harness is a Wayland clipboard editor and a launcher for longer Neovide sessions. Clipboard modes write a session file, open that file in Neovide, and copy the result back to the clipboard. Named sessions start from an empty directory with a git repository and do not touch the clipboard. An optional Neovim module copies a Markdown selection to the clipboard as HTML and pastes clipboard HTML back as Markdown. The editor modes are unchanged.

## Modes

| Command | Input | Ex commands after `--` | Clipboard MIME |
|---|---|---|---|
| `neovim.harness` | empty file | `+start` | `text/plain` |
| `neovim.harness -p` | `wl-paste --no-newline` | none | `text/plain` |
| `neovim.harness -m` | `wl-paste --no-newline -t text/html`, then Pandoc to GFM | `+colorscheme retrobox` | `text/html` |
| `neovim.harness -n` | empty file | `+start` then `+colorscheme retrobox` | `text/html` |
| `neovim.harness -s` / `--session` | `kdialog` title, then an empty directory and `git init -b main` | `+start` | none |
| `neovim.harness -r` / `--resume` | a session chosen in the picker | `+start` | none |
| `neovim.harness --clipboard-to-markdown` | `wl-paste --no-newline -t text/html`, then strict Pandoc to GFM | none | reads `text/html`; Markdown goes to stdout |
| `neovim.harness --markdown-to-clipboard` | UTF-8 Markdown on stdin, then strict Pandoc to HTML | none | writes `text/html`; stdout stays empty |

`-p`, `-m`, `-n`, `-s`, `-r`, `--clipboard-to-markdown`, and `--markdown-to-clipboard` are mutually exclusive. The default is new plain text. `-v` / `--verbose` enables debug logging. `--check-environment` only prints the full requirement report, including when a helper flag is also present, and does not convert anything.

## Invariants

- Clipboard sessions go to `~/.neovim.harness/sessions/doc-YYMMDDHHMMSS/doc-YYMMDDHHMMSS.md`. Nothing in the program deletes or expires them, so a later open of that folder can continue a `yapt.nvim` session.
- Named sessions go to `~/.neovim.harness/sessions/doc-YYMMDDHHMMSS--<title>/`. The title is asked with `kdialog --title "Neovim Harness" --inputbox <text>` before the directory exists. Cancel exits 0 and creates nothing. An unusable title asks again. No document file is created. `git init -b main` runs in that directory before Neovide, with no commit and no gitignore. If that git init fails, the new directory may be removed when it is empty or contains only `.git`.
- A title becomes a path segment: letters and digits stay, spaces become `-`, `--` collapses to `-`, and the segment is at most 80 characters and 200 UTF-8 bytes. The date prefix stays `doc-` plus 12 digits. A second directory with the same date and title gets `-2`, `-3`, …
- Resume lists directories matching that grammar, newest regular-file activity first. The picker is `neovide --no-fork -- --noplugin -i NONE -u NONE -c lua dofile(<resume.lua>)`, without the user config. Each row is one line: the recognizable name, the 12-digit date, then the modified time. The filter matches the full directory name. A space in the query matches a hyphen in that name, and repeated hyphens collapse to one. A query that is only hyphens after that normalization shows every session. Enter writes the directory and quits. If that write fails, the picker stays open, the user is notified, and a partial choice file is removed. Esc quits with no further launch. No sessions prints `No sessions to resume.` and exits 0. A path outside the session root, or a name that is not a session directory, opens an error dialog saying `Selected session is not in the session root.` A session name whose directory is gone says `Selected session no longer exists.` If the picker exits non-zero and writes no choice, the dialog says `Could not open the session list.` and the process exits 1. A chosen clipboard session opens `doc-….md` when that regular file exists. A symlink with that name is not the document. Resume does not run `git init` and does not use the clipboard.
- The picker preview is the first 10 lines of up to three newest text files. `.git`, `node_modules`, `__pycache__`, `.venv`, and `venv` are skipped. A NUL in the first 8 KiB, or text that is not UTF-8, is not previewed. Symlinks are not followed.
- `NEOVIM_HARNESS_SESSIONS` replaces that root only when the value is an absolute path. A relative value is ignored.
- If the timestamp directory exists, append `-2`, `-3`, … For a clipboard session the file stem matches the directory name, including the suffix. The session file mode is `0600`.
- Neovide's working directory is the session directory, not that directory's parent and not `$HOME`.
- A clipboard launch is `neovide --no-fork <file> --` plus the Ex commands, then `-c` to set the window title, then `-c lua dofile(<rename.lua>)`. The title is the session directory name, plus the buffer path relative to that directory when a file is open (`doc-YYMMDDHHMMSS/doc-YYMMDDHHMMSS.md`). An unnamed buffer shows only the directory name. `titlelen` is 0. A named launch omits `<file>`. stdin, stdout, and stderr are `DEVNULL`. `NEOVIM_HARNESS_RENAME_FILE` is a path outside the session.
- `:HarnessRename` saves named buffers, writes the request, then quits, and removes the request if quit fails. If any loaded modified buffer has no file name, the editor stays open and reports `Save unnamed buffers in this session, then run :HarnessRename again.` The request is not written. If the write fails, the editor stays open, the user is notified, and the request file is removed. After Neovide exits, a usable title renames the directory, keeps the date prefix, renames `doc-….md` when that file is present so its stem matches, initializes git when `.git` is absent, and opens Neovide again. A successful rename does not write the clipboard on that exit or from the editor that opens afterward. An unusable title leaves the directory in place, logs the reason, and opens Neovide again. If the directory was renamed and cannot be moved back, the dialog says the folder is already at the new path and the previous name could not be restored, and the editor opens in the directory that still exists. A missing request file ends the loop.
- A missing `neovide` executable, or any other launch failure, exits 1. If the editor fails before it returns, the rename-request temporary directory is removed. A normal return still lets that request be read.
- If the session file is gone after the editor exits, do not write the clipboard.
- Plain modes write only `text/plain`. Formatted modes write only `text/html`. Named and resumed sessions do not read or write the clipboard.
- Clipboard read is `wl-paste --no-newline`, plus `-t <mime>` when a MIME type is requested. Clipboard write is `wl-copy`, run in its own session with stdout and stderr discarded: the daemon it forks owns the selection, so it must neither keep the helper's stdout open nor join the helper's process group. Plain writes pass `-t text/plain` and formatted writes pass `-t text/html`. An empty MIME type omits `-t`. `read()` returns stdout when `wl-paste` fails and does not stop `wl-paste` on a timer. `read_required(mime)` uses that same argv and stops after 30 seconds. `wl-copy` stops after 30 seconds, a missing `wl-copy` becomes the same message as in the helper check, and any other failure reports `Could not copy <mime> to the clipboard.` When stderr says the type is unavailable (`Nothing is copied` or `not available as requested type`), the message is `The clipboard has no <mime> content.` Any other non-zero `wl-paste` reports that stderr, or `wl-paste failed.` when stderr is empty. A timeout says `Timed out waiting for wl-paste.` A missing `wl-paste` says `The wl-paste command is not on PATH.` An empty MIME type in `read_required` says `A clipboard MIME type is required.` A `wl-copy` timeout says `Timed out waiting for wl-copy.`
- HTML to Markdown: `pandoc -f html -t gfm-raw_html --wrap=none --lua-filter=<backics.lua>`. Empty HTML becomes an empty Markdown file and does not call Pandoc. `convert()` waits for Pandoc. For editor modes, a Pandoc failure returns an empty string. `convert_strict()` stops Pandoc after 30 seconds and raises that failure instead. A timeout says `Timed out waiting for pandoc.` This path does not import `lxml`, `premailer`, or `cssutils`. `backics.lua` writes a table as an unpadded pipe table when the table has no row or column span: every row is kept, so each header row after the first and each body header row becomes a body row, and `tfoot` rows are appended after the body rows; a table whose head holds no row takes the first row of the first body's head, which is where the reader puts a `<tbody>` header row, as its header row, and a table with no header row anywhere gets an empty one (`|  |  |` for that column count); each cell becomes one inline run with `<br>` between runs and at a hard break at any depth, and a block boundary that follows a hard break adds no second one; a `Div`, which is what the reader makes of a `<div>` or a `<section>`, a `BlockQuote`, and a `Header`, whose level is dropped, are flattened into the inlines they hold, a bullet list and an ordered list are flattened item by item with each item on a run of its own whose first run begins with `• ` or with the item number and a period counted from `start`, and raw HTML and element attributes are dropped as they are everywhere else in this output; a literal backslash is written as `\\` and a pipe as `\|`, both as raw inlines, because the writer drops a pipe that follows an odd run of backslashes and leaves a backslash before a letter alone, which the Markdown reader this project uses then reads as raw TeX that the HTML writer drops, while nothing is written for a pipe inside `Code` text or inside a link or image destination, because this project's Markdown reader keeps a pipe inside a code span, so escaping it would leave a visible backslash, and because the writer percent-encodes one in a destination; a GFM reader would split the cell at that pipe, which is the price of the round trip this project converts for; a line break, tab, or carriage return in a link or image title becomes a space, the title's padding is dropped, and its backslash, double quote, and pipe are escaped, because an unescaped quote ends the title early and the reader then drops the whole link, so the row stays one line and keeps its link; and a column takes its alignment from its column spec, or from the header cell when that spec has none. A caption is not part of the row block: the table is written the same way and the caption's blocks follow it unchanged, which is the trailing paragraph Pandoc already writes for a caption in GFM. A table with a row or column span, a table with a cell that holds a footnote reference, and a table with a cell that holds a code block or a nested table are left to Pandoc, which writes a pipe table when it can and `[TABLE]` when it cannot; every other block a cell can hold, such as an `<hr>`, a `<dl>` or a line block, falls back the same way. A table without the Pandoc 2.10 shape or with no columns, and a cell whose written run still spans more than one line, are left to Pandoc too.
- Markdown to HTML: `pandoc -f markdown+hard_line_breaks+lists_without_preceding_blankline -c <github-pandoc.css> --embed-resources --standalone`, then `premailer` with `remove_classes=True`, then lxml keeps only the `body` element's children. Premailer failure returns the Pandoc HTML. lxml failure, or a missing `body`, returns the inlined HTML. Those fallbacks stay successful for both `convert()` and `convert_strict()`. For editor modes, a Pandoc failure returns an empty string. `convert()` waits for Pandoc. `convert_strict()` stops Pandoc after 30 seconds and raises that failure instead. A timeout says `Timed out waiting for pandoc.`
- `--clipboard-to-markdown` and `--markdown-to-clipboard` exit 0 on success and 1 on a clipboard, Pandoc, UTF-8, or launch failure. Diagnostics go to stderr and never to the data stream. They do not create a session. `--clipboard-to-markdown` checks Pandoc, `wl-copy`, `wl-paste`, `WAYLAND_DISPLAY`, and the Pandoc filter and stylesheet. It does not check or import `lxml`, `premailer`, or `cssutils`. `--markdown-to-clipboard` also checks `lxml`, `premailer`, and `cssutils`. Neither check includes Neovide, git, kdialog, or the editor scripts. `--check-environment` stays the full check, including when a helper flag is also present. A failed `wl-copy` says `Could not copy text/html to the clipboard.` A missing `wl-copy` says `The wl-copy command is not on PATH.` Markdown that is not UTF-8 says `Markdown from stdin is not valid UTF-8.`
- The Neovim module lives at `share/nvim/site/pack/neovim-harness/start/neovim-harness/lua/neovim_harness/init.lua` and is installed under `/usr/share/nvim/site`. `require("neovim_harness").setup()` registers `:HarnessCopyHtml` and `:HarnessPasteMarkdown`. The default mappings are `<leader>mh` in visual mode and `<leader>mp` in normal and visual mode. `false` disables that mapping. Commands are registered either way. `setup()` can be called again. Neovim older than 0.10 makes `setup()` report `neovim_harness requires Neovim 0.10 or newer.` and register nothing. The copied text is `getregion()` and the replaced span is `getregionpos()`, so grapheme clusters, `'selection'`, and `'virtualedit'` columns match the highlight. A characterwise span that reaches a line break replaces that break too, because the highlight covers it: `'selection'`=`inclusive` counts a position past the last byte, `exclusive` counts column one of the next row, `old` leaves the break out, and an empty `exclusive` selection keeps one character. A `'virtualedit'` position past the last byte stops at that line's last real byte instead, even when it sits inside a virtual cell, and a span whose end sits inside a character keeps that whole character in every `'selection'` mode. The copied text keeps the break an `exclusive` selection covers, but `getregion()` drops one break when the span ends on an empty row and keeps one that `old` leaves out, so the copied text can differ from the replaced span by trailing newlines; a document-final newline does not change the HTML. A multi-line selection with a `'virtualedit'` position past the line end is read from that span instead, because `getregion()` aborts Neovim for that shape, so such a copy keeps no virtual padding. Characterwise and linewise selections are supported, including Select mode, which is read and left like Visual mode. Blockwise selection notifies `Blockwise selection cannot be converted.` and does not start a process. A one-address range such as `:2HarnessCopyHtml` uses that whole line. A two-address range whose lines differ from the last visual selection is linewise for both copy and paste. A two-address range on the same lines keeps that visual selection, including characterwise `:'<,'>`. `:1,1` and `:'<,'>` cannot be distinguished when both cover the same lines, so that case keeps the visual selection. Copy reads the selection before `vim.system({command, "--markdown-to-clipboard"})` and does not change the buffer. A copy of an empty or whitespace-only selection notifies `Select text before copying it as HTML.` and starts nothing, because blank Markdown becomes empty HTML and would empty the clipboard. Paste runs `vim.system({command, "--clipboard-to-markdown"})` with no stdin. Both helpers are started with `NEOVIM_HARNESS_PROCESS_GROUP=1`. The helper calls `setpgrp` only when that variable is `1`. Normal mode inserts after the cursor and leaves the cursor where `p` leaves it: on the first byte of the last grapheme of a single inserted line, and on the first inserted byte when the result spans lines. A cursor past the last byte under `'virtualedit'` inserts at that line's last real byte. Visual mode replaces the selection. One trailing newline is removed when it only terminates the document. That newline stays when the segment it terminates ends with a backslash or with two spaces. A successful empty Markdown result, including a result that becomes empty after that removal, does not change a visual selection and notifies `The converted Markdown is empty. The selection was left unchanged.` Normal-mode empty Markdown does nothing. The insert is one undo step. A newer copy or paste cancels the previous helper by signaling its process group with `sigterm` when the job pid is greater than 1. Negating pid 1 would signal every process the user may signal, so that pid is not negated. Otherwise the `vim.system` job is killed with `sigterm`, and ignores its callback: the callback does not insert, does not notify a changedtick failure, and does not replace the newer result. The later paste records `changedtick` after the earlier request is invalidated. Two pastes that finish one after another both insert. If `changedtick` changes before the current result arrives, the result is not inserted. An invalid buffer, a non-zero exit, or a missing program shows `vim.notify(..., ERROR)` and does not change the buffer. Processes are not run through a shell.
- Suppress `cssutils` logging to `CRITICAL` during Markdown-to-HTML conversion. `cssutils` is imported directly on that path. `lxml`, `premailer`, and `cssutils` load only when Markdown is converted to HTML.
- `backics.lua`, `github-pandoc.css`, `rename.lua`, and `resume.lua` are package data. Resolve them with `importlib.resources.as_file`. Pass the Pandoc paths to Pandoc and the editor scripts to Neovide.
- `:start` and `retrobox` are literal Ex commands from the user's Neovim config. This package does not install them and does not probe for them.
- Before the editor opens, run the same environment check as `--check-environment`. On failure, print the report and exit 1 without creating a session and without launching Neovide.

## Module boundaries

`cli.py` is the only composition root. It parses arguments and wires Wayland, Pandoc, Neovide, kdialog, and git. `app.py` is one sequence: open a workspace, prepare, run the editor, relocate while a rename was requested, then publish when the workspace still wants the clipboard. It has no mode branches and no subprocess calls.

| Change | Owner |
|---|---|
| Mode policy (input, Ex commands, output MIME) | `modes.py` — one class per workflow |
| Headless HTML and Markdown direction | `modes.py` — `ClipboardToMarkdown` and `MarkdownToClipboard`; `app.py` does not run them |
| Clipboard argv | `clipboard.py` |
| Pandoc argv and HTML fallbacks | `convert.py` |
| Package-data paths | `assets.py` |
| Session paths, slug, catalog, preview, rename | `sessions.py` |
| Which workspace opens, and rename after exit | `workspace.py` |
| kdialog argv | `prompt.py` |
| `git init` argv | `repository.py` |
| Neovide argv, working directory, detached streams | `editor.py` |
| Requirement report text | `environment.py` |
| Neovim selection, mappings, and `vim.system` | `share/nvim/site/pack/neovim-harness/start/neovim-harness/lua/neovim_harness/init.lua` |

A new workflow is a new mode class plus a CLI flag. Keep the `app.py` sequence as it is. Headless conversion follows that rule and does not enter `app.py`.

## Desktop files

Source files live in `share/applications/`. `Exec` is the PATH command `neovim.harness`, not an absolute path. `NoDisplay` is omitted. Each file sets `X-KDE-GlobalAccel-CommandShortcut=true`, `StartupNotify=false`, `Terminal=false`, `Icon=neovide`, `Categories=Utility;TextEditor;`, and `GenericName=Neovim clipboard editor`.

| File | Exec |
|---|---|
| `neovim.harness.new-plain.desktop` | `neovim.harness` |
| `neovim.harness.edit-plain.desktop` | `neovim.harness -p` |
| `neovim.harness.new-formatted.desktop` | `neovim.harness -n` |
| `neovim.harness.edit-formatted.desktop` | `neovim.harness -m` |
| `neovim.harness.new-session.desktop` | `neovim.harness -s` |
| `neovim.harness.resume-session.desktop` | `neovim.harness -r` |

## Tests

- `tests/unit/` uses fakes and `monkeypatch`. It must not read or write the real clipboard, launch Neovide, or create directories under the user's home. Session tests use `tmp_path`. `tests/unit/test_nvim_plugin.py` runs the Lua module in headless Neovim with `vim.system` mocked.
- `tests/pandoc/` runs the real Pandoc across the HTML and Markdown directions. It starts from hand-written browser-shaped HTML and not from Pandoc's own HTML output, and it covers the `backics.lua` table rewriting, the Markdown that rewriting produces, and that this Markdown is a fixed point of a further round trip.
- `tests/environment/` calls the real machine: real `PATH`, real imports, and the real `WAYLAND_DISPLAY`. It does not launch Neovide. Each failed assertion message is only that check's user-facing paragraph. `tests/environment/conftest.py` reprints the failures as one report.
- Driving the module from headless Neovim by hand loads the real configuration, and two things there look like a broken module. Use an empty working directory: `./?.lua` is first in `package.path`, so a scratch `cmp.lua` is required in place of the module a plugin really wants, and a scaffold that replaces `vim.system` and `vim.notify` then applies process-wide, which makes a copy report nothing and leave the clipboard alone because the converter never started. Do not block the event loop in a `vim.wait()` predicate: a blocking `vim.fn.system()` or `vim.fn.systemlist()` call stops the converter's callback, so the wait always reaches its timeout. Quit from a deferred callback and read the clipboard after Neovim exits; quitting first leaves the clipboard unchanged.

```sh
pytest tests/pandoc --tb=no -q
pytest tests/unit --cov=neovim_harness --cov-report=term-missing --cov-fail-under=90
pytest tests/environment --tb=no -q
```

To change a requirement message, edit `environment.py`, then the unit test that locks the wording, then the matching live test if the pass condition changed.

## Build and run

Install from the repo:

```sh
cd packaging/arch && makepkg -si
```

`check()` runs the environment suite, then the unit suite. `packaging/arch/neovim.harness.install` runs `neovim.harness --check-environment` from `post_install` and `post_upgrade` and does not swallow a failing exit code.

From a checkout, `pip install -e .` installs the console script. `PYTHONPATH=src python -m neovim_harness` runs the same entry point without installing it.
